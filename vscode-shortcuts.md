# ⌨️ VS Code Горячие клавиши — Шпаргалка Senior-разработчика

> **Цель**: Не просто список — это руководство по переходу с «нажимаю
> то, что вижу» на «работаю со скоростью мысли». Все шорткаты актуальны
> для VS Code 1.85+. Расширения не рассматриваются — только core.
>
> ⚡ — возможен конфликт с системными сочетаниями ОС

---

## 1. Навигация по файлам и рабочему пространству

Самая недооценённая область: большинство разработчиков тратят до 30%
времени на поиск нужного файла мышью. Эти шорткаты устраняют проблему
полностью. Ключевая идея — никогда не тянуться к мышке для смены контекста.

| Действие | Windows/Linux | macOS | Описание / Сценарий |
|---|---|---|---|
| Быстрое открытие файла | `Ctrl+P` | `⌘+P` | Нечёткий поиск по имени файла в проекте. Печатай часть имени — работает умнее, чем ты думаешь |
| Переключение между последними файлами | `Ctrl+Tab` | `⌃+Tab` | Зажми `Ctrl`, листай `Tab` — видишь превью всех открытых вкладок |
| Перейти к предыдущему файлу | `Ctrl+Alt+←` | `⌃+-` | Назад по истории навигации — как кнопка «Назад» в браузере |
| Перейти к следующему файлу | `Ctrl+Alt+→` | `⌃+Shift+-` | Вперёд по истории навигации |
| Закрыть текущую вкладку | `Ctrl+W` | `⌘+W` | Закрывает активный редактор |
| Переоткрыть закрытую вкладку | `Ctrl+Shift+T` | `⌘+Shift+T` | Как в браузере — возвращает последнюю закрытую вкладку |
| Переключиться на вкладку по номеру | `Ctrl+1..9` | `⌘+1..9` | `Ctrl+1` — первая вкладка слева, незаменимо при работе с 2–3 основными файлами |
| Перейти к строке | `Ctrl+G` | `⌃+G` | Вводишь номер строки, прыгаешь. Быстрее, чем скролл |
| Открыть Проводник (Explorer) | `Ctrl+Shift+E` | `⌘+Shift+E` | Фокус на файловом дереве |
| Переключить видимость сайдбара | `Ctrl+B` | `⌘+B` | Скрыть/показать весь левый сайдбар — даёт больше места для кода |
| Фокус на редакторе (из сайдбара) | `Escape` | `Escape` | Закрыть панель и вернуть фокус |
| Перейти к следующей/предыдущей группе | `Ctrl+K Ctrl+→` / `Ctrl+K Ctrl+←` | `⌘+K ⌘+→` / `⌘+K ⌘+←` | Переключение между split-редакторами без мыши |
| Показать все открытые редакторы | `Ctrl+K Ctrl+P` | `⌘+K ⌘+P` | Список всех открытых файлов в формате picker |
| Pinned вкладка | `Ctrl+K Shift+Enter` | `⌘+K Shift+Enter` | Закреплённая вкладка не закрывается по `Ctrl+W` — пинуй конфиги и README |

> **⚠️ Частая ошибка**: Использовать мышь для клика по вкладкам. При 10+
> открытых файлах это превращается в игру «найди нужную». Результат —
> постоянное отвлечение и потеря контекста. Используй `Ctrl+P` + часть
> имени файла: 2–3 символа обычно достаточно.

> **✅ Senior-совет**: В `Ctrl+P` можно вводить `имяфайла:номерстроки`,
> например `server:245` — откроет `server.ts` сразу на строке 245.
> Аналогично `@символ` ищет символы внутри файла. Это Quick Open, не просто
> поиск файлов.

## 2. Редактирование кода

Скорость редактирования определяется не быстротой набора, а количеством
операций, которые делаются за одно действие. Мультикурсор и операции
со строками — ядро продуктивности. Освоив этот раздел, ты начнёшь видеть
код как структуру, а не как текст.

| Действие | Windows/Linux | macOS | Описание / Сценарий |
|---|---|---|---|
| Мультикурсор вверх/вниз | `Ctrl+Alt+↑` / `Ctrl+Alt+↓` | `⌥+⌘+↑` / `⌥+⌘+↓` | Добавляет курсор выше/ниже. Идеально для редактирования колонок данных |
| Выделить все вхождения слова | `Ctrl+Shift+L` | `⌘+Shift+L` | Выделяет ВСЕ вхождения текущего слова в файле и ставит мультикурсор |
| Добавить следующее вхождение к выделению | `Ctrl+D` | `⌘+D` | По одному добавляет совпадения — можно пропустить ненужные через `Ctrl+K Ctrl+D` |
| Пропустить текущее вхождение | `Ctrl+K Ctrl+D` | `⌘+K ⌘+D` | Пропустить текущее и перейти к следующему при использовании `Ctrl+D` |
| Переместить строку вверх/вниз | `Alt+↑` / `Alt+↓` | `⌥+↑` / `⌥+↓` | Перемещает текущую строку или весь блок выделения |
| Дублировать строку вверх/вниз | `Shift+Alt+↑` / `Shift+Alt+↓` | `⇧+⌥+↑` / `⇧+⌥+↓` | Копирует строку без буфера обмена |
| Удалить строку | `Ctrl+Shift+K` | `⌘+Shift+K` | Удаляет строку без буфера — в отличие от `Ctrl+X` не затирает clipboard |
| Форматировать документ | `Shift+Alt+F` | `⇧+⌥+F` | Форматирует весь файл согласно настроенному форматтеру |
| Форматировать выделение | `Ctrl+K Ctrl+F` | `⌘+K ⌘+F` | Форматирует только выделенный фрагмент |
| Закомментировать строку/блок | `Ctrl+/` | `⌘+/` | Строчный комментарий. Работает с мультикурсором |
| Блочный комментарий | `Shift+Alt+A` | `⇧+⌥+A` | `/* */` — блочный комментарий вокруг выделения |
| Свернуть блок | `Ctrl+Shift+[` | `⌥+⌘+[` | Сворачивает текущий блок (функцию, класс, if) |
| Развернуть блок | `Ctrl+Shift+]` | `⌥+⌘+]` | Разворачивает свёрнутый блок |
| Свернуть все | `Ctrl+K Ctrl+0` | `⌘+K ⌘+0` | Свернуть всё в файле — взгляд на структуру с высоты птичьего полёта |
| Развернуть все | `Ctrl+K Ctrl+J` | `⌘+K ⌘+J` | Развернуть всё |
| Свернуть на уровень N | `Ctrl+K Ctrl+1..9` | `⌘+K ⌘+1..9` | Сворачивает до нужного уровня вложенности |
| Выделить строку целиком | `Ctrl+L` | `⌘+L` | Выделяет текущую строку. Нажать повторно — добавит следующую |
| Перейти к соответствующей скобке | `Ctrl+Shift+\` | `⌘+Shift+\` | Прыгает к парной скобке — незаменимо при разборе вложенных структур |
| Транспонировать символы | `Ctrl+T` (не всегда работает) | — | Меняет два символа местами |
| Изменить отступ строки | `Ctrl+]` / `Ctrl+[` | `⌘+]` / `⌘+[` | Увеличить/уменьшить отступ выделения |
| Вставить курсор в конец каждой строки выделения | `Shift+Alt+I` | `⇧+⌥+I` | Незаменимо для добавления `;` или `,` к нескольким строкам сразу |
| Выделение прямоугольником ⚡ | `Shift+Alt+drag` / `Ctrl+Shift+Alt+↑↓` | `⇧+⌥+drag` | Колоночное выделение — редактировать данные как таблицу |
| Undo последнего курсора | `Ctrl+U` | `⌘+U` | Убирает последний добавленный курсор, не отменяя текст |

> **⚠️ Частая ошибка**: Ручное переименование переменной через
> `Ctrl+H` (Find & Replace). Это опасно — можно случайно заменить
> вхождения в комментариях или строках, и не учитывает область видимости.
> Используй `F2` для семантического переименования (раздел 7).

> **✅ Senior-совет**: `Ctrl+D` + `Ctrl+D` + ... для точечного выбора
> нужных вхождений, потом редактирование — мощнее глобального
> replace. Например, переименовать переменную `data` только в трёх
> из десяти мест файла без риска сломать остальные.

## 3. Поиск и замена

Встроенный поиск VS Code — полноценный инструмент с regex, scope и
preserve case. Большинство разработчиков не используют и 20% его
возможностей. Научись читать файл как базу данных — ищи символы,
не только текст.

| Действие | Windows/Linux | macOS | Описание / Сценарий |
|---|---|---|---|
| Поиск в файле | `Ctrl+F` | `⌘+F` | Открывает панель поиска в текущем файле |
| Поиск и замена в файле | `Ctrl+H` | `⌥+⌘+F` | Замена с preview — всегда проверяй перед «Replace All» |
| Следующее/предыдущее совпадение | `F3` / `Shift+F3` | `F3` / `⇧+F3` | Навигация по совпадениям без мыши |
| Выбрать все совпадения поиска | `Alt+Enter` | `⌥+Enter` | В активной панели поиска — выделяет ВСЕ совпадения как мультикурсор |
| Поиск по всему проекту | `Ctrl+Shift+F` | `⌘+Shift+F` | Глобальный поиск — открывает панель Search |
| Замена по всему проекту | `Ctrl+Shift+H` | `⌘+Shift+H` | Глобальная замена — смотри diff перед применением! |
| Regex-режим поиска | `Alt+R` (в панели поиска) | `⌥+R` | Переключает regexp. `(\w+)\s+(\w+)` → `$2 $1` меняет слова местами |
| Match case | `Alt+C` (в панели поиска) | `⌥+C` | Учёт регистра |
| Whole word | `Alt+W` (в панели поиска) | `⌥+W` | Искать только целые слова |
| Поиск по символам в файле | `Ctrl+Shift+O` | `⌘+Shift+O` | Список всех функций/методов/переменных файла. Введи `:` для группировки |
| Поиск по символам в проекте | `Ctrl+T` | `⌘+T` | Глобальный поиск символов — находит функцию по имени во всём workspace |
| Перейти к определению (через Quick Open) | `Ctrl+P` → `#имя` | `⌘+P` → `#имя` | `#` в Quick Open ищет символы по всему workspace |
| Command Palette | `Ctrl+Shift+P` | `⌘+Shift+P` | Поиск любой команды VS Code — вход в «Бога-режим» |
| Поиск файла по имени | `Ctrl+P` | `⌘+P` | Нечёткий поиск файлов. `?` — список действий |
| Свернуть панель поиска / Escape | `Escape` | `Escape` | Закрывает панель поиска и возвращает фокус в редактор |
| Искать в выделении | `Alt+L` (в панели поиска) | `⌥+L` | Ограничивает поиск выделенным фрагментом |
| Preserve Case при замене | кнопка `AB` в замене | кнопка `AB` | Умная замена: `foo`→`bar`, `Foo`→`Bar`, `FOO`→`BAR` |

> **⚠️ Частая ошибка**: Скроллить файл вручную в поисках функции.
> При файле в 500+ строк это занимает десятки секунд. `Ctrl+Shift+O`
> даёт структуру файла мгновенно, плюс нечёткий поиск по имени метода.

> **✅ Senior-совет**: В глобальном поиске (`Ctrl+Shift+F`) используй
> поля `files to include` и `files to exclude` с glob-паттернами:
> `**/*.test.ts` или `!**/node_modules`. Это на порядок ускоряет
> поиск в монорепозиториях с тысячами файлов.

## 4. Работа с терминалом

Встроенный терминал — не просто консоль, а полноценный менеджер
сессий. Правильная работа с ним исключает необходимость переключаться
между VS Code и внешним терминалом, сохраняя контекст workspace.

| Действие | Windows/Linux | macOS | Описание / Сценарий |
|---|---|---|---|
| Открыть/скрыть терминал | `` Ctrl+` `` | `` ⌃+` `` | Тогглит панель терминала. Один из самых используемых шорткатов |
| Создать новый терминал | `Ctrl+Shift+\`` | `⌘+Shift+\`` | Новая сессия терминала рядом с текущей |
| Разделить терминал | `Ctrl+Shift+5` | `⌘+Shift+5` | Split: два терминала рядом. Один для сервера, другой для команд |
| Следующий терминал | `Ctrl+PageDown` | `⌃+PageDown` | Переключиться на следующий терминал в списке |
| Предыдущий терминал | `Ctrl+PageUp` | `⌃+PageUp` | Переключиться на предыдущий терминал |
| Убить текущий терминал | через Command Palette | через Command Palette | `Terminal: Kill the Active Terminal Instance` |
| Очистить терминал | `Ctrl+K` (в фокусе терминала) | `⌘+K` | Очистить вывод терминала |
| Прокрутить вверх/вниз | `Ctrl+↑` / `Ctrl+↓` | `⌘+↑` / `⌘+↓` | Прокрутка без мыши |
| Прокрутить на страницу | `Shift+PageUp` / `Shift+PageDown` | `⇧+PageUp` / `⇧+PageDown` | Постраничный скролл вывода |
| Увеличить/уменьшить шрифт терминала | `Ctrl+=` / `Ctrl+-` | `⌘+=` / `⌘+-` | |
| Переключить фокус редактор↔терминал | `Ctrl+\`` / `Ctrl+1` | `⌃+\`` / `⌘+1` | Переключение без мыши |
| Максимизировать панель терминала | `Ctrl+B` (скрыть sidebar) + `Ctrl+J` | `⌘+B` + `⌘+J` | Скрыть сайдбар + показать/скрыть панель. Больше места для логов |
| Переименовать терминал | ПКМ на вкладке | ПКМ на вкладке | Добавить имя: «server», «tests», «db» — незаменимо при 5+ терминалах |
| Запустить Task | `Ctrl+Shift+B` | `⌘+Shift+B` | Запуск дефолтного Build Task. Tasks — мощный способ стандартизировать команды |

> **⚠️ Частая ошибка**: Открывать отдельное окно терминала ОС для
> запуска команд. Это разрывает контекст: нужно помнить, в какой
> директории ты находишься. Встроенный терминал VS Code автоматически
> открывается в корне workspace и связан с текущим проектом.

> **✅ Senior-совет**: Используй несколько именованных терминалов
> с конкретными ролями: `dev-server`, `tests`, `git`, `logs`. Создай
> задачу в `tasks.json` для запуска всех сразу через `Compound Tasks`
> — один `Ctrl+Shift+B` поднимает весь стек разработки.

## 5. Git и система контроля версий

VS Code имеет полноценный Git-клиент, большинство операций доступны
без CLI. Связка Git + VS Code позволяет делать атомарные коммиты
с точным контролем над изменениями, не выходя из редактора.

| Действие | Windows/Linux | macOS | Описание / Сценарий |
|---|---|---|---|
| Открыть Source Control | `Ctrl+Shift+G` | `⌘+Shift+G` | Панель SCM — список изменённых файлов, staged и unstaged |
| Stage текущего файла | `Ctrl+Shift+G` → `+` | `⌘+Shift+G` → `+` | Stage файла целиком через UI |
| Stage выделенных строк | выделить → ПКМ → Stage Selected Ranges | аналогично | Staged только нужные строки — для атомарных коммитов |
| Просмотр diff файла | `Ctrl+Shift+G`, клик по файлу | аналогично | Diff view: было / стало side-by-side |
| Commit с сообщением | `Ctrl+Enter` (в поле сообщения SCM) | `⌘+Enter` | Коммитит staged изменения |
| Открыть встроенный diff | `Ctrl+Shift+G` → файл | аналогично | Или через `Ctrl+K V` в diff-режиме |
| Timeline (история файла) | View → Open View → Timeline | аналогично | История изменений конкретного файла — как `git log -p` |
| Открыть Gutter blame | наведи мышь на строку | аналогично | Inline blame при наведении — кто и когда изменил строку |
| Checkout ветки | `Ctrl+Shift+P` → `Git: Checkout` | `⌘+Shift+P` → `Git: Checkout` | Быстрое переключение веток через Command Palette |
| Создать ветку | `Ctrl+Shift+P` → `Git: Create Branch` | `⌘+Shift+P` → `Git: Create Branch` | |
| Revert изменений файла | `Ctrl+Shift+G` → файл → ↩ | аналогично | Откат изменений файла до HEAD |
| Merge Editor | появляется при конфликте | аналогично | 3-way merge editor — выбери incoming/current/both по кнопке |
| Открыть в Merge Editor | `Ctrl+Shift+P` → `Merge Editor` | аналогично | Для сложных конфликтов с перемешанными изменениями |
| Просмотр incoming/outgoing | Status Bar → sync icon | аналогично | Счётчик коммитов за/перед origin в статусбаре |
| Stash изменений | `Ctrl+Shift+P` → `Git: Stash` | `⌘+Shift+P` → `Git: Stash` | |

> **⚠️ Частая ошибка**: `git add .` + коммит всего сразу. Это
> убивает читаемость истории и делает ревью невозможным. Stage
> конкретных строк через SCM — создавай атомарные коммиты, каждый
> из которых делает ровно одно логическое изменение.

> **✅ Senior-совет**: В diff-редакторе можно stage/unstage
> отдельные **hunk'и** (блоки изменений) через кнопку `+` рядом
> с каждым блоком. Это позволяет из одного изменённого файла
> создать несколько коммитов с разным контекстом — без `git add -p`
> в терминале.

## 6. Отладка (Debug)

Отладчик VS Code — универсальный инструмент: поддерживает Node.js,
Python, Go, Java, C++ и другие через launch configs. Знание шорткатов
отладки сокращает время диагностики бага в разы по сравнению с
`console.log`-отладкой.

| Действие | Windows/Linux | macOS | Описание / Сценарий |
|---|---|---|---|
| Запустить / продолжить выполнение | `F5` | `F5` | Start debugging / Continue после паузы |
| Пауза | `F6` | `F6` | Приостановить выполнение в любой момент |
| Остановить отладку | `Shift+F5` | `⇧+F5` | Завершить сессию отладки |
| Restart | `Ctrl+Shift+F5` | `⌘+Shift+F5` | Перезапустить сессию — быстрее, чем Stop + Start |
| Step Over (шаг через) | `F10` | `F10` | Выполнить строку, не заходя в функцию |
| Step Into (шаг внутрь) | `F11` | `F11` | Зайти внутрь вызова функции |
| Step Out (шаг наружу) | `Shift+F11` | `⇧+F11` | Выйти из текущей функции к месту вызова |
| Поставить / убрать breakpoint | `F9` | `F9` | Тогглит breakpoint на текущей строке |
| Conditional breakpoint | ПКМ на gutter → Add Conditional BP | аналогично | Точка останова с условием: `i === 42 && error !== null` |
| Logpoint (без остановки) | ПКМ на gutter → Add Logpoint | аналогично | Выводит в console без остановки — замена `console.log` с авто-удалением |
| Открыть Debug Console | `Ctrl+Shift+Y` | `⌘+Shift+Y` | REPL в контексте точки останова — можно выполнять выражения |
| Открыть панель отладки | `Ctrl+Shift+D` | `⌘+Shift+D` | Показать Variables, Watch, Call Stack |
| Добавить Watch | выдели выражение → ПКМ → Add to Watch | аналогично | Отслеживать значение выражения между шагами |
| Inline values | автоматически при паузе | аналогично | VS Code показывает значения переменных прямо в коде |
| Выбрать конфигурацию запуска | `Ctrl+Shift+D` → dropdown | аналогично | Переключение между launch configs без редактирования JSON |
| Run Without Debugging | `Ctrl+F5` | `⌃+F5` | Запустить без отладки — быстрее, нет overhead дебаггера |

> **⚠️ Частая ошибка**: Отлаживать через `console.log`, который
> нужно потом удалять. Logpoint (`F9` → conditional → logpoint)
> выводит в Debug Console и автоматически не попадает в коммит —
> это временный инструмент без побочных эффектов.

> **✅ Senior-совет**: Используй `launch.json` с несколькими
> конфигурациями: отдельно для unit-тестов, для конкретного файла,
> для remote debugging. `Ctrl+Shift+D` + dropdown позволяет
> переключаться между ними в один клик. Compound launch config
> запускает несколько процессов одновременно (например, frontend + backend).

| Breadcrumbs навигация | `Ctrl+Shift+.` (фокус) | `⌘+Shift+.` | Путь файл→класс→метод вверху редактора — клик для навигации |

> **⚠️ Частая ошибка**: Открывать файл с реализацией через Ctrl+P
> и ручной поиск. `F12` сделает это за тебя за 0 секунд, с точным
> попаданием на нужную строку. При этом `Alt+F12` (Peek) ещё лучше —
> не нужно терять текущий контекст.

> **✅ Senior-совет**: `F2` (Rename Symbol) работает через LSP и
> понимает область видимости. В TypeScript проектах переименовывает
> символ во всём workspace, включая импорты, с учётом shadowing.
> Это не Find & Replace — это рефакторинг. После переименования
> всегда проверяй diff в SCM.

> Используй Profiles для изоляции: Python-профиль, Go-профиль,
> Web-профиль — только нужные расширения для каждого.

> **✅ Senior-совет**: `.code-workspace` файл коммить в репозиторий
> вместе с `extensions.json` в `.vscode/`. Так весь проект
> получает правильные рекомендованные расширения, launch configs

## ⚙️ Кастомизация: keybindings.json

Открыть: `Ctrl+Shift+P` → `Open Keyboard Shortcuts (JSON)` или `Ctrl+K Ctrl+S` → иконка `{}`.

```jsonc
// keybindings.json — примеры полезных переопределений
[
  // Сохранить все файлы (Ctrl+K S по умолчанию сохраняет без форматирования)
  {
    "key": "ctrl+shift+s",
    "command": "workbench.action.files.saveAll"
  },

  // Закрыть ВСЕ редакторы (а не только текущий)
  {
    "key": "ctrl+k ctrl+w",
    "command": "workbench.action.closeAllEditors"
  },

  // Переключение между терминалом и редактором без мыши
  {
    "key": "ctrl+`",
    "command": "workbench.action.terminal.toggleTerminal",
    "when": "!terminalFocus"
  },
  {
    "key": "ctrl+`",
    "command": "workbench.action.focusActiveEditorGroup",
    "when": "terminalFocus"
  },

  // Быстро открыть недавний проект
  {
    "key": "ctrl+shift+r",
    "command": "workbench.action.openRecent"
  },

  // Переместить строку с Alt стрелками (уже есть по умолчанию — проверь)
  {
    "key": "alt+up",
    "command": "editor.action.moveLinesUpAction",
    "when": "editorTextFocus && !editorReadonly"
  },
  {
    "key": "alt+down",
    "command": "editor.action.moveLinesDownAction",
    "when": "editorTextFocus && !editorReadonly"
  },

  // Stage текущего файла из редактора (без перехода в SCM)
  {
    "key": "ctrl+k ctrl+g",
    "command": "git.stage"
  },

  // Быстрый коммит
  {
    "key": "ctrl+k ctrl+enter",
    "command": "git.commitStagedSigned"
  },

  // Отключить неудобный Ctrl+W (закрытие вкладки) если часто промахиваешься
  // РАСКОММЕНТИРУЙ если нужно:
  // { "key": "ctrl+w", "command": "-workbench.action.closeActiveEditor" },

  // Expand/shrink selection
  {
    "key": "shift+alt+right",
    "command": "editor.action.smartSelect.expand",
    "when": "editorTextFocus"
  },
  {
    "key": "shift+alt+left",
    "command": "editor.action.smartSelect.shrink",
    "when": "editorTextFocus"
  },

  // Go to next/prev change в diff editor
  {
    "key": "alt+f5",
    "command": "workbench.action.editor.nextChange",
    "when": "editorTextFocus"
  },
  {
    "key": "shift+alt+f5",
    "command": "workbench.action.editor.previousChange",
    "when": "editorTextFocus"
  }
]
```

### Полезные `when`-контексты

| Контекст | Значение |
|---|---|
| `editorTextFocus` | Курсор в редакторе |
| `terminalFocus` | Фокус в терминале |
| `inDebugMode` | Активна отладка |
| `editorHasSelection` | Есть выделение |
| `resourceExtname == .ts` | Текущий файл — TypeScript |
| `!editorReadonly` | Файл не read-only |
