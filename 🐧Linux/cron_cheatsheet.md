# Шпаргалка — cron

---

## Синтаксис

### Формат crontab (`crontab -e`)
```
минута час день_месяца месяц день_недели команда
```

### Формат `/etc/cron.d/` (добавляется поле пользователя)
```
минута час день_месяца месяц день_недели ПОЛЬЗОВАТЕЛЬ команда
```

### Поля времени

| Поле | Значения | Пример |
|------|---------|--------|
| минута | 0–59 | `30` = в 30 минут |
| час | 0–23 | `2` = в 02:00 |
| день месяца | 1–31 | `15` = 15-го числа |
| месяц | 1–12 | `6` = в июне |
| день недели | 0–7 (0 и 7 = воскресенье) | `0` = воскресенье |

### Спецсимволы

| Символ | Значение | Пример |
|--------|---------|--------|
| `*` | Любое значение | `* * * * *` = каждую минуту |
| `*/n` | Каждые n единиц | `*/5 * * * *` = каждые 5 минут |
| `n,m` | Несколько значений | `0,30 * * * *` = в 0 и 30 минут |
| `n-m` | Диапазон | `1-5 * * * *` = минуты 1,2,3,4,5 |

---

## Примеры задач

```bash
# Каждый день в 02:00
0 2 * * *   backup  /opt/backup.sh

# Каждое воскресенье в 03:00
0 3 * * 0   webapp  /opt/cleanup.sh

# Каждые 5 минут
*/5 * * * * webapp  /opt/check_site.sh

# Каждый первый день месяца в 00:00
0 0 1 * *   root    /opt/monthly_report.sh

# По будням в 09:00
0 9 * * 1-5 root    /opt/workday_task.sh
```

---

## Где хранить задачи

| Путь | Когда использовать |
|------|-------------------|
| `/etc/cron.d/myapp` | ✅ Системные задачи — используй это |
| `crontab -e` | Личные задачи пользователя |
| `/etc/crontab` | Системный crontab — не редактируй напрямую |
| `/etc/cron.daily/` | Скрипты запускаемые раз в день |
| `/etc/cron.weekly/` | Скрипты запускаемые раз в неделю |

### Почему `/etc/cron.d/` лучше `crontab -e`
- Файлы видны в системе — можно положить в git и деплоить через ansible
- Разные файлы для разных задач — `/etc/cron.d/db_backup`, `/etc/cron.d/monitoring`
- Явно указывается пользователь от которого запускается задача
- `crontab -e` — "магия в голове у пользователя", никто не знает что там без ручной проверки

## Шаблон файла в `/etc/cron.d/`

```bash
# /etc/cron.d/db_backup
# Описание: бэкап БД каждый день в 02:00

SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# минута час день месяц день_недели пользователь команда
0 2 * * * backup /usr/bin/env bash /opt/backup.sh
```

> ⚠️ Комментарии на отдельной строке, не в конце строки с задачей

## Шаблон скрипта для cron

```bash
#!/usr/bin/env bash
SITE="mysite.ru"

# curl с таймаутом — без этого зависшие процессы накапливаются
STATUS=$(curl -sL -o /dev/null -m 10 -w "%{http_code}" "$SITE")

if [[ "$STATUS" != "200" ]]; then
    # Timestamp в логе — без него непонятно когда упало
    echo "$(date +"%Y-%m-%d_%H-%M-%S") Site: ${SITE} HTTP Status: ${STATUS}" >> /var/log/mysite.log
fi
# Нет вывода если всё хорошо — cron не шлёт лишние email
```

### Правила скриптов для cron
- Всегда указывай полный путь к командам (`/usr/bin/curl`, не просто `curl`)
- Ставь таймаут на сетевые запросы (`-m 10` для curl)
- Добавляй timestamp в логи
- Не выводи ничего при успехе — cron шлёт email при любом stdout
- Перенаправляй ошибки: `2>> /var/log/myapp_error.log`

## Диагностика

```bash
# Проверить что задача запустилась
grep CRON /var/log/syslog
grep CRON /var/log/cron          # на RHEL/CentOS

# Посмотреть все задачи пользователя
crontab -l
crontab -l -u webapp             # задачи конкретного пользователя

# Проверить синтаксис (не встроено, используй crontab -e и смотри ошибки)
crontab -e                       # при сохранении покажет ошибку если синтаксис неверный

# Проверить пользователя для сервисных задач
id backup
grep backup /etc/passwd          # должно быть /sbin/nologin или /bin/false — не /bin/bash
```

## Частые ошибки

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Задача не запускается | Неверный синтаксис | Проверь `/var/log/syslog` |
| Скрипт не найден | Нет полного пути | Используй `/usr/bin/env bash /opt/script.sh` |
| Команда работает руками но не в cron | Нет переменных окружения | Добавь `PATH=...` в начало файла |
| Email спам от cron | Скрипт выводит текст при успехе | Убери лишний вывод или добавь `>/dev/null` |
| Процессы накапливаются | Нет таймаута на сетевые запросы | Добавь `-m 10` для curl, `timeout 30` для команд |
